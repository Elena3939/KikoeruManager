# 库存浏览器拖拽上传

## 实现入口

- 后端：`browser_upload_routes.py`、`browser_upload_service.py`、`browser_upload_storage.py`。
- 前端：`useLibraryExternalUpload.js`、`useBrowserUploads.js`、`BrowserUploadBatch.vue`。
- 独立接口：`/api/library/browser/uploads`，不经过会解压或扫描的旧上传入口。
- PostgreSQL 迁移：`20261023_0001_browser_uploads`，必须完整镜像发布。

## 行为与资源限制

外部文件拖到目录行、列表空白或面包屑后，固定实际库存 ID 和目标路径，直接启动传输。保留顶层名称、子目录和空目录；内部拖拽移动继续使用原链路。不能唯一定位的虚拟目录禁止投放。

默认每块 8 MiB，浏览器多个批次共享三个文件并发名额，单文件顺序传块。目录分页增量枚举，摘要在 Worker 中计算，兼容 HTTP 页面。来源文件留在浏览器，服务端只接收分块，不使用电脑绝对路径。

小窗区分接收与写入，包含文件状态、速度、失败阶段、原因、冲突决策和单文件重试。暂停与取消会中止在途请求；取消保留已落地文件。刷新后需要重新选择来源并校验分块摘要。

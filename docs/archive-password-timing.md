## 当前实现口径

- extract_runtime.ActiveClock 通过协程上下文累计工作时间；实际申请资源时使用 exclude_active_time，嵌套排除不会重复扣减。
- 所有候选和兼容后端共用已消耗工作预算；不再使用任务开始后的墙钟截止时间，也不通过外层 wait_for 包住排队。
- 7z、兼容 7z 后端与 Python ZIP 内容验证申请同一个解压槽，持续排队并响应暂停、取消。Python 工作线程实际开始后才创建执行截止时间。
- 取得资源后，通过 probe_execution_timeout 将单次执行时限限制在剩余工作预算内。真实进程超时仍会终止进程，超时不能当成密码错误或验证成功。
- probe 统计排除资源等待；同阶段嵌套调用只统计一次，完整测试和 Python ZIP 内容验证也记录探测阶段。execution 继续表示占用解压资源期间的工作累计，包含探测进程；probe 是其中的业务阶段，不能再与 execution 相加当作墙钟。
- 默认小条目时限 60 秒、前缀探测 30 秒、流式探测 60 秒、整包验证首轮 180 秒、重试 600 秒；候选累计工作预算为 1800 秒。排队和用户暂停不计入这些工作预算。
- 任务元数据增加 password_validation_elapsed_ms、password_validation_budget_ms、password_validation_budget_exhausted，用于区别实际耗尽预算与普通未定结果。通用未定文案不再无证据地推断资源不足。

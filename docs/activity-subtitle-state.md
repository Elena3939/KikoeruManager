# 操作历史的单任务字幕配对状态

字幕抓取和随后手动配对通过真实 `task_id` 关联，是同一任务的处理阶段。单任务抽屉用“处理过程”展示抓取、重试和配对记录，不表示创建了新的子任务；批量任务继续保留关联事件和成员结构。

抓取阶段的 `waiting` 和 `awaiting_manual_match=true` 是当时的审计事实。读取时，最新抓取之后的最新配对事件为 `success`，列表和详情均展示配对完成、清除待配对标记，并使用配对摘要；原始数据库记录不回写。更早轮次的配对不能完成后续重新抓取。状态筛选在 SQL 分页前采用相同的配对结论。

轻量列表只对当前页字幕任务批量查询最新配对的状态、摘要、时间及数量，不加载 `pair_changes` 文件清单，不按行请求数据库。详情继续使用原有业务聚合结构和完整配对映射。

配对映射取消固定前 8 项的截断，长文件名允许换行。详情滚动区的业务面板禁止 flex 收缩，避免长面板的下半段被后续面板或底部按钮覆盖。命名策略显示“按音频名”或“按字幕名”。

回归：`backend/tests/test_activity_subtitle_state.py` 覆盖审计不变、旧轮次隔离、跨页完成状态、SQL 状态筛选和详情一致性。`tools/check-activity-subtitle-layout.mjs` 使用真实详情组件，验证 9 项映射、长名称、浅色/暗色及 390–960 像素宽度的滚动和溢出。

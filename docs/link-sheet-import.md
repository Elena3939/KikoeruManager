# Excel 链接库

设置页的「Excel 链接库」接受固定格式 XLSX，先后台解析和预览，再确认发布。
只处理 RJ；表内异常作品保留旧清单，其余正常作品原子切换；未出现的作品不变。
资源按标签组合与归档集合分组，PAR2 只用于追溯。相同名称、相同大小的不同链接是候选副本，
默认使用首条候选，不能据此认定文件内容相同。预览与导入不请求 MEGA。
同名不同大小不再判作品异常：单文件拆成独立可选资源组，展示大小；后续重名项固定使用
`文件 (2).exe` 等保存名称，编号避开表内已有名称，不因重试或目标文件存在而变化。
MEGA 元数据仍核对原始名称，只有保存名称增加编号。大小写不同的同名路径也按此隔离。
链接库中的大小只作为导入时的参考；下载开始时以 MEGA 返回的正实际大小为准，
即使表内大小已变化也继续下载，不把该差异判为错误。
同名分卷按表内顺序拆成不同方案，唯一的卷供各方案共用；不从大小推断配套关系，
预览提示核对配套，各组使用独立目录且保留全部卷名。不完整方案不能提交下载。
同一归档同时出现 `part01` 和 `part1` 等不同编号格式时，拆成独立资源组分别检查连续性，
例如 `part01.exe～part06.rar` 与 `part1.rar～part4.rar` 可独立选择，各组隔离目录，不改原名。
单套分卷跨越第十卷不因此拆组；真实缺卷仍报异常。
文件 S 为零、缺失或无法解析时保留原值，显示“大小待核实”，不因此判定作品异常。
下载开始、重试和恢复时读取 MEGA 元数据：保留文件名校验，只有表内提供有效正大小时才比较大小；
使用 MEGA 返回的真实正大小检查已完成文件和下载完整性。获取失败仍走下载失败处理，不在导入阶段联网。
启动时修正待发布批次中旧规则产生的大小、同名、分卷错误及统计，并从已有文件记录重建分组，
保留其他异常，不自动发布，也不修改已发布修订和已有任务引用。

下载按组创建 HTTP 任务，保存修订、组和候选文件引用。开始、重试、恢复使用同一修订，
核对 MEGA 文件名后传输，大小以 MEGA 元数据返回值绑定到任务，完成后检查实际字节数。
新导入不改变旧任务。
下载到目录即完成，后续解压继续使用已有流程与密码库。

管理面板复用库存的 Element Plus 分页及 `km-pagination-wrap` 样式，支持页码、跳页和每页 10/20/50/100 条，默认 10 条；后端按 `page_size` 查询并将越界页码收敛到最后一页。作品标题单行截断，悬浮可看全文，详情保留完整内容。作品表按当前页内容自然展开，不设置表内纵向滚动；
导入历史收进右上角统一 `AppDropdown` 版本选择器，显示文件名、导入时间及状态，可切回当前生效清单；历史按 20 条翻页查询，通过较新/更早记录切换，不在作品表底部重复展示历史列表。
空表保留桌面 360px、移动端 300px 的最小高度，复用 `AppEmptyState` 的 No Data 动画。
等待和解析期间在表格区域显示 `AppLoadingAnimation`，每 1.5 秒刷新“已入库 RJ 行 / 入库总数”和百分比；
总数通过流式预读去重后的 RJ 标识获得，不解析文件 JSON，不使用可能包含空行的工作表 dimension。
当前数量与每批修订、文件在同一事务提交，重复和非 RJ 行不计入分母；统计总数期间显示“统计中”，不虚构百分比。
解析期间隐藏未完成明细和分页，完成后才展示分页明细，并用系统结果弹窗列出详细统计、重复行和耗时；
直接查看已完成历史不会重复弹出。暗色加载说明、进度和表头小字使用白色，样式仅作用于链接库面板。
按钮按压、加载和完成态保持内容位置与尺寸稳定，刷新使用原图标匀速旋转。
Lottie 播放器 WASM 随前端构建发布，由应用提供，不依赖外部 CDN。

## 接口

管理列表的操作为“详情”和“获取下载链接”，不提供行内启用复选框。
获取下载链接按点击读取该修订详情，仅展示非 PAR2 文件的完整链接，不触发 MEGA 请求或下载；
详情仍保留完整元数据和 PAR2 追溯记录。

- `POST /api/link-sheet/imports`：流式上传，100 MiB 上限，返回批次 ID。
- `GET /api/link-sheet/imports`、`GET /api/link-sheet/imports/{id}`：分页历史及状态。
- `POST /api/link-sheet/imports/{id}/confirm`、`cancel`：发布或取消。
- `GET /api/link-sheet/works`：按 `page/page_size/search/batch_id/errors_only` 分页查询，每页最多 100 条。
- `GET /api/link-sheet/revisions/{id}`：管理修订详情，返回原始元数据、完整文件链接（含密钥）、字节大小、原始 S 值和 PAR2 标记；仅此详情入口显示明文，下载任务、来源预览、日志、SSE 和通知仍脱敏。
- `PATCH /api/link-sheet/works/{rjcode}`：`{"enabled": false}` 停用新提交，不影响已提交任务。
- 来源提交使用 `source_provider=link_sheet`、`revision_id`、`selected_resources`；
  每个选择包含组 `id` 和按组文件顺序排列的 `candidate_ids`。

后台通过 PostgreSQL 会话锁串行解析，逐批写入；进程中断的解析会标为 interrupted。
重新上传即可重新解析。终止后删除上传临时文件；修订与任务引用保留。
发布与停用通过同一事务登记受影响社团的增量物化，批次状态单独返回社团更新状态。

## 数据库与发布

迁移为 `20261109_0005_link_sheet`，上一个版本是 `20261106_0004_circle_work_events`。
新增四张表：`link_sheet_imports`、`link_sheet_revisions`、`link_sheet_files`、`link_sheet_current`。
迁移不修改已有业务表；降级会删除新表，不得对已写入业务数据的环境自动执行降级。

线上按授权流程使用 PostgreSQL MCP：读取 production profile、连接、刷新 schema，
核对实际 Alembic 版本和待执行链，准备备份后执行对应增量 DDL。
可在仓库根目录离线生成本迁移 SQL：

```powershell
& ./backend/venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade 20261106_0004_circle_work_events:20261109_0005_link_sheet --sql
```

SQL 来源保持为 Alembic 迁移，不另外维护手写建表版本。
确认前置迁移已全部执行后，才同步本迁移版本记录。不能直接将版本跳到未执行的 head。
建表和版本记录在同一事务中验证；对存量大表没有数据重写，新对象的创建仍需要正常 DDL 锁。

数据库准备完毕后，按项目 SSH 入口验证生产主机及 MEGA 依赖，
使用仓库发布脚本同步源码和前端产物。本功能没有增加 Python 或前端依赖。
当前联合发布脚本未将 Alembic 目录作为上传范围，线上结构必须在同步前通过 MCP 完成。
如果生产尚未安装 MEGAcmd 和当前下载器所需依赖，使用完整镜像发布。
代码发布失败时恢复旧应用，保留兼容的新表；不自动删除已导入数据。

## 验证

批量预览的链接库计划通过当前指针 JOIN 修订一次读取，每 500 个去重 RJ 分块；
空集合不发 SQL，不查询文件链接表。单作品计划复用同一查询入口。
本地来源描述按批读取，生成计划时复用当前请求内的清单和社团上下文；
混合来源合并同样复用该清单，不逐作品重新查 Excel。发布、停用后的新请求重新查库，
提交仍按当前修订校验，下载任务仍固定已提交的修订和候选，不引入长期清单缓存。
本地 PostgreSQL 的 120 RJ 受控测试：旧式指针及修订读取 240 条 SQL / 109.22ms，
新入口读取并构造计划 1 条 SQL / 4.48ms。仅代表本地清单阶段，不代表整弹窗或网络下载耗时。

社团补全的下载弹窗沿用来源选择器，在 asmr.one、YAAS、Excel 链接库之间切换。
Excel 资源组默认不选，可多选，并在组内切换候选链接；提交仅包含当前来源、固定修订和候选 ID。
切换站点保留候选选择，不将另一来源的文件混入提交。
本地发现的可下载版本仅有 Excel 来源时，直接读取已发布清单，不请求 DLsite、ASMR 或 MEGA；
有其它来源时保留既有语言发现及来源对比流程，同时补入本地 Excel 命中的原作或展示版本。
社团索引建立 / 刷新时也会对每个作品的 canonical、展示 RJ 和关联链 RJ 查询启用中的 `link_sheet_current`，并把命中状态写入索引完成操作记录的来源对比；操作记录与社团补全页面使用同一套妙蛙种子来源事实。
ASMR 增强下载的 RJ 输入使用同一个来源计划接口和下载预览弹窗；
输入多个 RJ 时先批量读取 Excel 当前修订，再分别生成 asmr.one、YAAS、Excel 链接库选项。
提交后的三种来源统一进入增强下载任务工作台，Excel 任务仍固定修订和候选文件 ID。
MEGA 元数据解析与文件名、大小核对在实际开始下载时执行，预览不暴露完整下载链接。

后端测试：`tests/test_link_sheet.py`，并回归 `test_resource_source_service.py` 和 `test_http_download_service.py`。
前端测试覆盖默认不选、多组提交、候选切换及 HTTP 任务操作。
整表性能工具为 `tools/benchmark-link-sheet.py`，只接受环境变量
`KIKOERUMANAGER_TEST_DATABASE_URL` 指向的专用 `*_test` 数据库，并连续执行两次导入检查幂等。
该工具会创建测试表并保留测量数据，不能指向业务数据库。

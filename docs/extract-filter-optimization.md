# 解压链路、过滤与恢复区本地改造记录

本轮仅本地修改、验证和提交，未发布、未修改生产配置。原始基准见 `extract-filter-benchmark.json`，复现脚本为 `tools/benchmark-extract-filter.py`。

## 调度与正确性

- 7zz、unar、路径重映射和 Python ZIP 实际执行统一使用可调整的共享解压限流器；容量变化不清空在途计数。旧 `archive_cpu` 仅读取兼容、保存排除，不再二次限制实际解压。清单和密码探测仍使用独立资源预算。
- 等待计时覆盖申请到获得全部资源，取消释放已取得的槽；参数兼容重试先释放再申请。嵌套使用有界 worker，扫描不因条目预算截断，深度耗尽明确报告未完成。
- 文件稳定检查核对大小、纳秒修改时间和文件身份，并确认可读；取消不再依赖固定小文件等待。
- 密码保留精确字符及候选来源；保留无密码路径，全部明文 ZIP 直接无密码解压。父密码仅非空且父层实际成功后享有一次不限短探测时长的实际解压机会。子包及兄弟包证据隔离，不记录明文密码。
- 使用加密小条目验证；魔数、有限前缀及通用 CRC/Data Error 不单独证明密码错误。前缀密码字节证据只选择兼容后端，最终必须完整读取。中文 GBK ZipCrypto 嵌套包可进入 Python 兼容后端；取消时等待工作线程退出后才释放执行槽。
- ZIP 文件名代码页参数不传给 RAR/7z；参数错误不污染其他密码。编码尝试使用独立目录及内容核对，原地修名遇碰撞拒绝覆盖。Python ZIP 解码按条目尊重 UTF-8 标志。
- 编码缓存绑定文件身份/大小/mtime，限制容量；密码负证据还绑定工具及参数。最终清单完整性核对改全量，不再抽样或因替换字符直接放行；已取得清单时，不允许旧关闭校验配置跳过。

## 父子链路耗时

`extract_timing.version=1` 保存节点 ID、父 ID、深度、尝试及单调时钟事件。实际解压、完整资源排队、清单、探测、扫描及校验分开记录。`extract_execution_duration_ms` 保留原累计语义。

父包执行 30 秒 → 子包排队 60 秒 → 子包执行 20 秒 → 孙包执行 10 秒：最终文件链路解压为 **60 秒**，等待为 **60 秒**。兄弟包占槽与其他任务占槽同样是当前链路等待。每条链包含共同祖先；任务累计按唯一节点事件计算，不将各链总值相加，并行累计不作为墙钟。

任务详情展示当前归档、深度、状态数量、进程累计、墙钟及链路明细；历史和通知统一标签。无旧区间证据的记录不回填精确等待。外层完成不提前设为 95%，未知工作量不虚构总百分比。

## 过滤与恢复事务

工作线程一次 scandir 复用 stat，生成文件树及音频分布；冻结规则并预编译。路径组件树传播父目录命中、后序累计大小，固定规则和深度下近线性。仅 MP3 的保护行为保留。扫描、规划、搬运提供暂停/取消检查，批量回传字节及条目进度。

恢复区保留持久化路径，格式为 `task.json`、`entries/{recovery_id}.json` 与 `payload`。每项准备和提交分别原子写入，不再每收一项重写全清单。旧 manifest 在任务锁内迁移，读回校验后发布 v2 标记；旧文件不删除。重试创建独立批次，保留旧内容、目标及路径映射。

同卷移动，跨卷分块复制、SHA-256 核对、发布后才删除源。复制前后核对源文件身份与目录成员，源发生变化拒绝删除。capture、restore、finalize、cleanup 共用任务锁。启动在线程中核对中断记录，开始重试及恢复前也核对；无法判断归属的内容保留并标记 incomplete。回滚失败报告实际 staged/payload 路径。

## 实测基准

Windows 本机 Python 3.12.10；规划每组取三次中位数，单位 ms。

| 规划场景 | 1 万文件 | 5 万文件 | 10 万文件 |
| --- | ---: | ---: | ---: |
| 宽目录 | 23.24 | 127.75 | 246.75 |
| 固定 8 层深目录 | 39.09 | 211.64 | 401.79 |
| 父子目录同时命中 | 20.45 | 147.52 | 248.79 |
| MP3 保护后的无命中模型 | 17.24 | 119.72 | 209.95 |
| 零命中 | 17.56 | 120.25 | 214.21 |

真实创建 16 字节小文件，实际搬运和持久化，不包括创建测试文件耗时：

| 文件数 | 扫描 ms | 搬运并持久化 ms | 首次汇总 ms | 原子条目写入次数 |
| --- | ---: | ---: | ---: | ---: |
| 10,000 | 76.45 | 58,188.39 | 2,040.89 | 20,000 |
| 50,000 | 410.17 | 302,032.78 | 11,348.41 | 100,000 |
| 100,000 | 799.29 | 622,449.74 | 22,755.78 | 200,000 |

事件循环延迟 p95 **6.44 ms**，最大 **68.09 ms**。规划及元数据工作量接近线性；10 万小文件搬运仍约 **622 秒**，每项两次 fsync/原子写入存在明显耐久性成本，首次全汇总仍需约 23 秒，后续读取缓存。未做旧实现同机对照，不声明加速倍数；未测 NAS 跨卷吞吐。MP3 基准模拟保护后的规则，保护正确性由回归用例验证。

## 验证范围与剩余边界

后端定向回归覆盖限流扩缩容和取消、双队列释放、祖先及兄弟链路、候选隔离、全量末尾缺失条目、编码、过滤规则、旧恢复接口、多批次及中断、跨卷失败和源目录变化。真实本机 7-Zip 26.02 覆盖明文 ZIP、不同密码 ZIP、头加密及中文密码无后缀 7z；构造真实 GBK ZipCrypto 混合条目包验证嵌套兼容解压。前端活动详情测试和生产构建另行执行。

最终定向结果：后端 **269 passed、1 skipped**（16.81 秒），前端活动详情 **6 passed**，Vite 生产构建及静态预压缩成功。未运行全仓库 pytest；构建保留依赖的 PURE 注释、eval 及大分包提示。

以下不能视为全部验收：Linux 官方 7zz 24.08/unar/lsar 实机矩阵、RAR 多编码及混合密码真实大包、缺卷与不支持方法实物集合、实际磁盘耗尽/权限故障和硬断电。部分故障通过注入验证。无可用清单时仍依赖后端完整执行退出结果，无法提供与已知清单同等级的逐项证据；旧 `unknown` 探测返回协议保留，部分原因通过候选证据细分。兼容参数错误目前逐次调整，未新增跨调用工具能力缓存。线程内文件系统检查无法阻止外部程序在最后核对与删除之间改动源，执行期间不应由外部程序修改输入。

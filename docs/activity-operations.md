# 操作历史的操作、执行、事件与指标

> 2026-11-12 回退说明：操作历史页面和原有列表、统计、详情、子项接口已恢复原业务聚合读取，不再切换到本文的精简操作投影；原详情组件、业务字段、文件树和母子任务展示保留。以下投影设计和基准为此前实现记录，不代表当前页面读取方式。派生表和原始审计数据未删除，写入一致性修复保留；不得据本文自动发布投影或重建线上数据。

## 统计口径

社团 `index_completed` 详情使用独立的 `index_snapshot` 内部读取契约：从同一已发布代际读取作品及 `compare_payload`，保留逐作品来源证据；普通详情、全选仍使用轻量投影。写日志前必须等到有效发布头追上请求序列，超时作为本次索引失败处理，不能写成成功的空记录。

建立或刷新社团时，在关联链确定后持久化 YAAS 待探测编号，与后续 ASMR 核对和元数据处理重叠执行；排除未发售作品，普通索引保留有效缓存、重排过期结果，强刷重排已结论编号。操作记录保存当时的 YAAS 命中、待探测、未命中、失败状态，以及妙蛙种子的命中 RJ；后台探测不阻塞整社团索引，完成记录不会自动改写成探测后的状态。

操作详情在原始快照之外返回 `source_probe_observation`（观察时间及逐作品当前来源）。只使用记录里已有的原作、展示编号和关联链，批量读取两张来源表，不加载其它社团或全量目录。界面保留“索引时”的统计，单列当前 YAAS 各状态和妙蛙种子已对比/命中数；YAAS、妙蛙种子的逐行标签及筛选使用当前观察。旧记录缺少来源证据时不能把当前状态伪造为历史结果，当前来源也不反向改写历史的已收录/可下载总数。重新打开详情会重新读取当前来源。

DLsite 翻译标题读取共用原始 product.json 的连接池、并发去重及索引任务快照；不同 locale 保持隔离，保留日文假名校验，不额外触发完整元数据/特典请求。关联链任务获得并发槽后再次检查缓存，强刷只复用本轮新解析的链，索引开始前已有的链仍重新验证。

单社团完成记录自带完整业务快照，详情接口直接读取该记录，不按批次或任务加载其它社团再聚合。详情中的原始 JSON 只在展开时序列化并挂载，来源列表和业务字段保持完整。

操作数以业务类型及明确的操作、批次、会话身份计数。一次提交、下载或上传会话计一个操作；用户独立提交的重试使用新操作身份。自动重试使用原操作内的新执行身份。同 RJ、相近时间、相同摘要不能作为合并依据。旧记录没有可靠关系时单独保留，并显示信息缺失。

执行由操作、任务或会话及尝试身份确定。`attempt_id`、`execution_id`、`attempt_no` 用于区分真实重新执行。事件是原始 `activity_logs` 记录，继续使用 `event_key` 幂等。操作卡片数不等于事件数，事件数也不能代表文件数。

指标由执行、阶段和指标名唯一确定。完整清单优先于摘要，摘要优先于文件事件的临时累计；同一次执行的业务终态与任务收尾不重复计量。重试对父记录的结果投影不贡献指标。已知零值保留为零，大小或耗时未知显示“未知”；删除容量是已知容量之和，大小未知的文件数单列。

时间统一使用北京时间半开区间 `[开始日 00:00, 结束日次日 00:00)`：

- 操作数、分类和状态分布按发起日，重试修复后的结果仍归原操作发起日。
- 下载、上传、入库、解压等实际工作量按执行完成日。
- 最新活动时间只负责排序和显示更新。

因此跨日操作可以出现在一天的操作卡片、另一天的工作量中。页面明确展示两种日期依据。

## 状态和归属

列表、详情、状态筛选、统计和重建共用 `activity_operation_normalizer.py`。前端只格式化服务端结果。

批次写入 `schema_version=2`、`scan_closed`、`producer_closed` 及 `submitted_count`。扫描或投递尚未关闭、实际成员数与预期不等时显示“结果未收齐”；等待人工处理显示“待处理”。全部成功、全部失败、全部取消分别显示对应状态；混合终态显示部分成功。

每个成员按事件时间及事件 ID 的稳定顺序更新，更新的失败、取消不会被更早的成功覆盖。原始失败保留在事件中；父操作收到成功重试投影后显示“已修复”。多库同路径使用库存身份区分。父压缩包没有单一 RJ 是合法数据。

## 表与事务

- `activity_log_operations`：每代每个操作一行，保存当前结果、原始结果、成员计数、修订号和紧凑展示内容。
- `activity_log_operation_events`、`activity_log_operation_members`：唯一事件归属和成员当前态。
- `activity_log_metric_facts`：真实执行的阶段指标。
- `activity_log_operation_files`：保留文件清单，按库、路径和执行身份区分。
- `activity_log_operation_daily`：操作发起日及指标完成日的分类、状态日汇总。只计算受影响操作的旧、新贡献，事务内执行差额更新；零值存在性单独保留，避免零变成未知。
- `activity_log_projection_state`：当前可读代际、构建代际、检查点。
- `activity_log_projection_repairs`：派生维护失败的持久修复标记。
- `activity_log_detail_archives`：历史压缩前的原始 JSON 压缩存档。

原始写入、状态回写、操作投影、指标和日汇总共享事务。普通派生维护失败会记录待修复标记；可靠审计写入沿用事务与 outbox 重试。待修复时新读路径返回可重试错误，不能把故障表现为零统计。

操作锁与代际门闩防止重复收尾和发布竞态；日汇总按照固定桶顺序更新。提交后失效旧列表、行和详情缓存，并通过 Redis 发布修订通知。新投影读取 PostgreSQL，不依赖 Redis 缓存的新鲜度。

## 读取与分页

现有 `/api/activity-logs` 路径保持兼容。投影完成对账并发布后，列表从操作投影分页，默认 50、最高 200 条。搜索通过原始记录索引命中所属操作，再返回完整操作；不把 5,000 条搜索窗口当作真实总数。

`include_stats=true` 让列表和统计在同一 `REPEATABLE READ` 事务快照内返回。页面整体应用这份响应，失败保留旧内容。默认统计及分类、状态筛选读取日汇总；包含搜索、批次或会话条件时使用数据库聚合对应操作及指标。列表和统计禁止扫描全部历史 JSON。

详情默认加载前 100 个事件及文件。`/{id}/children`、`/{id}/files` 使用游标分页，返回 `total`、`next_cursor`、`has_more`；游标绑定操作、代际及阶段。`/{id}/events/{event_id}` 按需加载原始 JSON。压缩前已丢失的内容不能恢复，接口与页面保留完整性标记。

下载、远程上传和本地入库分别展示。平均速度为阶段有效字节除以阶段耗时；任一有字节贡献的执行缺少有效耗时，整体平均速度显示未知。

## 核对和重建

### 已通过 MCP 应用数据库变更时的增量同步

用户明确授权直接修改生产数据库时，先通过 PostgreSQL MCP 核对全部迁移表、字段、约束和索引，补齐缺失结构后再登记 Alembic 版本，不得仅修改版本号跳过迁移。此流程不执行历史投影重建，也不把 `ready=false` 改为已就绪。新增索引可以单独删除回滚；已有业务表和数据不重建。

数据库结构已与迁移完全一致且运行时依赖未变化后，可用 `deploy-production-local-build.ps1 -AppliedMigrationFiles 'backend/alembic/versions/20261111_0006_activity_operations.py'` 显式携带已应用的迁移文件。该参数只同步文件，不执行数据库变更；迁移文件与源码共用备份、SHA 校验、语法检查和失败恢复，保证容器重启时 Alembic 能解析已登记版本。

命令使用当前运行配置，运行前必须确认指向本地或已获授权的目标数据库。以下是工具用法，不代表已经执行线上重建。

```powershell
& ./backend/venv/Scripts/python.exe tools/rebuild-activity-operations.py
& ./backend/venv/Scripts/python.exe tools/rebuild-activity-operations.py --start-date 2026-11-11 --end-date 2026-11-11
```

默认只读，输出事件覆盖、成员和指标守恒、孤儿记录、日汇总差异，以及按日、分类、状态和指标的业务账单。`before` 是活动代际，`expected` 是候选代际；没有候选时报告会注明无对照基线。日期只限制报告，不缩小重建和发布闸门的覆盖范围。

```powershell
& ./backend/venv/Scripts/python.exe tools/rebuild-activity-operations.py --rebuild --chunk-size 500
& ./backend/venv/Scripts/python.exe tools/rebuild-activity-operations.py --publish
```

重建写隔离代际，按日期和 `(created_at, id)` 检查点分批提交，支持中断续跑。在线新增事件同时维护活动代际和构建代际。发布持有独占门闩，重放待修复操作，核对全部原始事件及日汇总，成功后一次切换代际；不允许部分新旧数据混读。发布失败时旧代际保持可读，未修复派生故障仍明确报错。旧代际保留用于核对，尚未提供自动清理策略。

应用启动后会后台续建尚未就绪或已有构建代际的操作投影，每批最多 500 个原始事件、批间让出 100ms，并复用上述全量发布闸门。已就绪且无候选代际时直接退出，不重复重建。异常保留隔离代际和检查点，记录错误，不切换读取；重启可续跑。该入口不开放新的 HTTP 权限，不改变原始事件或已发布代际。

原始事件日统计使用 `activity_log_daily_stats_service.rebuild_daily_stats(db, start_date, end_date, apply=False)`，默认只读；授权修复后 `apply=True`，由调用方提交。它与新操作日汇总是不同口径，不能互相相加。

## 验证与边界

回归覆盖 ASMR 双终态、文件与摘要重叠、重试投影、乱序取消、迟到父记录、跨日执行、多库路径、等待人工、零和未知、251 个文件分页、宽搜索、回滚及幂等重建。数据迁移包含升降级验证。

本地基准：

```powershell
& ./backend/venv/Scripts/python.exe tools/benchmark-activity-operations.py --operations 1000 --repetitions 20
node tools/check-activity-operation-layout.mjs
```

性能结果保存于 `outputs/activity-performance.json`，包含 1,000／10,000 个合成操作、6,000／60,000 个事件的读延迟、SQL 次数、响应体、Python 内存采样、查询计划及单线程／四线程写入吞吐。首次请求不等于清空 PostgreSQL 和操作系统缓存后的冷启动；Python 内存采样不代表宿主 RSS。不能把本地合成测试称为生产等量验收。

界面证据在 `outputs/activity-layout/`，覆盖 2K 和移动端、浅色／暗色、列表／详情／重试错误及 251 个文件翻页；使用浏览器真实渲染和模拟接口，不能代替生产真实记录验收。

本次本地实现不包含生产部署、线上数据写入、历史重建或提交。生产发布需要先应用迁移、只读核对、授权后构建新代际，并通过真实数据对账和业务验收。

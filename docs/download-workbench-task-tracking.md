# 下载工作台任务跟踪

## 适用范围

本规则覆盖 ASMR 同步页中的 HTTP 外链下载和百度网盘下载工作台。

## 跟踪合同

- 下载创建接口返回的任务 ID 是来源工作台的跟踪依据。
- `/api/http-download/status` 和 `/api/baidu-netdisk/status` 返回的是某一时刻的状态快照，只负责更新已返回任务的展示数据，不能据此删除未返回的已跟踪任务 ID。
- 新任务追加到当前工作台时置顶并去重；只有用户关闭工作台时才清空该工作台的跟踪 ID。
- 状态刷新使用递增请求序号。旧请求晚于新请求返回时必须丢弃，不能覆盖新任务、进度或 loading 状态。
- 状态任务按 ID 建立索引后再映射到工作台顺序，避免任务数量增加后逐项线性查找。

## 状态缓存合同

- 下载状态缓存只有在任务中心版本一致且缓存未超过 TTL 时才能复用。
- 任务提交、状态变化或进度事件导致版本变化后，即使旧缓存仍在 TTL 内也必须立即失效。
- 缓存用于减少同版本高频状态序列化，不能牺牲任务新增和状态变化的可见性。

## 回归检查

1. 保持一个下载任务运行，随后追加第二个任务。
2. 确认第二个任务立即出现在来源工作台，后台轮询期间不消失。
3. 连续手动刷新并等待自动轮询交错返回，确认任务顺序和数量稳定。
4. 关闭工作台后确认在途状态请求不会重新填充已清空的任务列表。

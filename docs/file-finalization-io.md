# 大文件最终发布与跨卷搬运

百度网盘临时转存下载和 ASMR 增强下载都可能从临时卷搬到下载卷或库存卷。不同 Docker 挂载点之间的 `rename` 会退化为整文件复制，因此搬运不能直接运行在 asyncio 主线程。

## 运行约束

- 同卷优先使用 `os.rename`，跨卷统一走 `move_path_efficient()` 的流式复制。
- 跨卷复制在线程池执行，并占用 `disk_io_local` 资源预算；不能占住 HTTP / SSE 所在事件循环。
- 百度网盘先写目标目录下的 `.kikoerumanager-moving-*` 临时文件，大小校验通过后再原子发布正式文件。
- 取消时停止后续复制、保留源文件并清理发布临时文件；不能把半成品标记为下载完成。
- 发布进度按时间和字节节流，不能按每个复制块写任务运行态。

## 验证口径

- 大文件发布期间 `/api/health`、任务中心和 SSE 保持响应。
- watchdog 不应出现由 `shutil.move` / `os.sendfile` 引起的事件循环停顿。
- 成功后正式文件大小等于源文件；失败或取消后不存在 `.kikoerumanager-moving-*` 残留。

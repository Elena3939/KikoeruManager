# 解压入库重命名断点重试

## 行为

- 解压和元数据获取成功后，如果作品目录重命名失败，任务固定记录为 `failure_stage=rename`，任务中心显示“重命名失败”。
- 重命名失败时保留本次解压目录，不执行失败产物清理；问题作品中的重试直接使用该目录。
- 重试任务从重命名阶段继续，复用首次获取的元数据，不重新解压、不重新执行重复预检。
- 断点保存首次自动入库的过滤、智能分类和归档开关；续跑不受“已有文件夹处理”开关影响，重命名必定重新执行。
- 重命名成功后继续过滤、扁平化、字幕处理、智能分类和社团拥有态同步；首次任务需要归档原压缩包时，断点重试成功后继续加入延后归档队列。

## 关联作品预检

- DLsite 关联链确定原作后，ready 库存索引命中的目标目录可直接提供补配/重复判断。
- 目标目录无字幕时进入字幕补配；目标目录已有字幕时按关联作品重复进入问题作品。
- Kikoeru 查询失败但 ready 库存目标明确时，不再把结果降级为“关联状态不确定”。

## 验证重点

- 重命名失败目录及目录内文件在任务失败后仍存在。
- 问题作品重试创建 `process_existing_folder` 任务，来源路径为保留的解压目录。
- 断点重试不调用元数据获取，且重命名成功后仍执行智能分类和社团拥有态同步。
- ready 库存关联目标分别覆盖“缺字幕可补配”和“已有字幕重复”两类结果。

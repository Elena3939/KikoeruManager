# 任意后缀 7z 分卷的嵌套解压

嵌套目录扫描在密码探测前调用 `ExtractService._repair_opaque_7z_volumes()`，先恢复具有明确顺序证据的卷名，再交给现有分卷解压、密码候选、完整性校验和入库流程。

## 顺序依据

- 同目录 `.bat` / `.cmd` 中的 `ren` / `rename` 支持带引号的精确文件名，以及 `*.旧后缀 → *.7z.001` 形式的后缀映射，也支持单体 `*.旧后缀 → *.7z`。只解析声明，不执行脚本；路径跳转、变量、命令拼接等内容不参与映射。
- 没有脚本时，按相同文件主体收集任意后缀候选。7z 固定头及其 CRC 确认首卷；仅接受两卷，或首卷和中间卷等长、唯一末卷更短的三卷组合。多段等长中间卷无法证明顺序时明确停止，不按任意后缀的数字或字典序猜测。
- 已有标准 `.7z.001` 等文件沿用原链路，不重复规范化；扫描只调度首卷，非首卷不单独生成嵌套解压任务。原有 ZIP / RAR 伪装分卷逻辑继续保留。

## 校验与性能

每个候选组合先验证固定 32 字节头的 CRC、卷组总长、Next Header 长度和 CRC。Next Header 随机定位，最多读取 1 MiB，不拼接、复制或全量扫描大分卷。该结构校验不替代后续解压器对实际内容及密码的验证。

改名前统一检查目标重复和文件碰撞；发生中途改名错误时按反序恢复已改名文件。缺卷、顺序不唯一、映射冲突及头校验失败直接中止本次扫描，不再把结构问题转为密码候选轮查。任务元数据 `opaque_volume_renames` 保存实际旧路径、新路径，日志包含规范化数量。

改名只发生在嵌套解压产物目录，外层来源压缩包保持原样。正常嵌套解压成功后复用原有清理逻辑删除整组标准卷；失败继续由外层任务的清理及问题作品流程处理。

## 验证

`backend/tests/test_opaque_volume_rename.py` 覆盖声明映射、无脚本唯一顺序、随机 ASCII 后缀、缺卷、CRC 错误、目标碰撞、冲突映射、改名回滚、脚本不执行、嵌套入口只调度首卷，以及真实加密 7z 分卷的恢复和内容核对。

Windows 定向测试从 `backend` 运行，使用项目虚拟环境及独立临时目录：

```powershell
$pytestTemp = Join-Path $env:TEMP ('kikoeru-volumes-' + [guid]::NewGuid().ToString('N'))
& .\venv\Scripts\python.exe -m pytest tests/test_opaque_volume_rename.py -q --noconftest --basetemp $pytestTemp
```

`--noconftest` 只适用于本文件无需数据库夹具的测试；不代表数据库集成验证。真实解压用例要求本机存在 7-Zip。

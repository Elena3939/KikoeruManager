## 已确认的问题

2026-11-11 的线上只读排查发现，`auto_import` 原始事件与旧日账的状态分布不一致。下表保留当次快照，不代表当前线上已修复：

| 状态 | 原始事件 | 旧日账 |
| --- | ---: | ---: |
| cancelled | 4 | 1 |
| failed | 5 | 5 |
| incomplete | 30 | 32 |
| partial_success | 1 | 0 |
| pending | 25 | 25 |
| success | 59 | 57 |
| waiting | 18 | 22 |

两侧总数均为 142，但总数一致不能证明状态账正确。重试回写父事件时缺少旧桶扣减、新桶增加，是需要修复的写路径。

当次 ASMR 原始事件共 82 条，包含 35 条上传事件、16 条会话完成、16 条任务结束和 15 条会话开始。既有会话合并与终态隐藏有效，不能将原始双终态直接认定为页面重复。新回归测试核对操作归属和指标贡献。

另外修复了统计日期窗口不一致、多套状态推断、清单截断、错误显示成空结果、零值被未知覆盖，以及部分成功的原始结果被折叠成失败的问题。

## 性能

基准使用本地 PostgreSQL，1,000 / 10,000 个合成操作分别对应 6,000 / 60,000 条事件，每项 20 次请求。数值是服务函数延迟，不包含网络及浏览器耗时。

| 指标 | 1,000 操作 | 10,000 操作 |
| --- | ---: | ---: |
| 50 条列表首次请求 | 150.759 ms | 6.562 ms |
| 50 条列表暖请求 p95 | 5.504 ms | 4.954 ms |
| 搜索列表暖请求 p95 | 8.660 ms | 51.495 ms |
| 日汇总统计暖请求 p95 | 0.775 ms | 0.777 ms |
| 分页详情暖请求 p95 | 5.250 ms | 5.307 ms |
| 列表 SQL 数量 | 3 | 3 |
| 统计 SQL 数量 | 1 | 1 |
| 详情 SQL 数量 | 7 | 7 |
| 列表响应体 | 51,056 B | 51,301 B |
| 列表 Python 内存采样峰值 | 464,112 B | 470,322 B |

日汇总引入前，10,000 操作的统计暖请求 p95 为 39.368 ms、4 次 SQL；引入后为 0.777 ms、1 次 SQL。完整查询计划、内存采样和响应体数据见 `outputs/activity-performance.json`。

| 写入方式 | 旧 rollup | 新操作投影及日汇总 |
| --- | ---: | ---: |
| 单线程 | 1,806.44 事件/秒 | 2,593.63 事件/秒 |
| 四线程合计 | 1,474.44 事件/秒 | 2,874.22 事件/秒 |

本地合成负载通过延迟与写入吞吐门槛。没有清空数据库和操作系统缓存，首次请求不能称为真实冷缓存；Python 内存采样不是进程 RSS。生产等量真实分布、十倍真实分布、网络端到端 p95、真实冷缓存与宿主 RSS 尚未验收。

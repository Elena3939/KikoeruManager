# HTTP 下载完成判定

## 完成条件

HTTP 下载文件只有同时满足以下条件才允许进入 `completed`：

- 下载请求正常结束，没有取消、超时或网络异常。
- 有服务端声明大小时，实际落盘字节数必须与声明值完全相等。
- 多文件任务的 `completed_files` 必须等于 `total_files`，且 `failed_files` 为 `0`；否则只能进入失败或部分失败。
- 未完成标记已消失：Transfer.it 使用 `.part`，aria2 使用 `.aria2` 侧车。

## 文件发布边界

- Transfer.it 主下载路径始终写入 `<文件名>.part`，校验通过后使用原子替换发布正式文件名。
- 同一进程内同一个 Transfer.it 最终路径只允许一个任务写入；重复任务会在触碰 `.part` 前失败，避免两个流并发追加造成文件损坏。
- transferit-py 兼容路径先下载到 `storage.temp_path/transferit_fallback` 隔离目录，再校验大小并通过 `.part` 发布；中断时下载根目录不会出现正式压缩包。
- 重试时若发现历史版本遗留的正式文件大小与远端声明不一致，会把它迁回 `.part` 继续断点下载，不让文件监控提前消费。
- aria2 数据文件旁存在同名 `.aria2` 侧车时，文件处理器不创建解压任务；侧车删除后才允许进入压缩包识别链路。

## 失败语义

- 实际大小小于或大于声明大小都属于下载不完整，不能用实际大小反向覆盖预期大小后标记成功。
- 目录里只有一个文件不能作为成功依据，`.part` 等半成品禁止被兜底改名为正式文件。
- 下载失败保留可续传的 `.part`，任务中心记录已下载字节和失败原因，但不会把它展示为已完成文件。
- Transfer.it 开始任务时会重新解析分享。旧选择无法按节点标识或文件名恢复时，任务明确报告“文件标识已变化”，不会退化为空文件列表或下载未选择的文件。
- Gofile 首次下载沿用配置的分片和超时；因超时进入自动重试后逐轮降低单文件分片数，并延长连接与无数据等待时间。失败信息保留具体 CDN 主机和是否收到过数据，便于区分节点线路故障与落盘校验失败。

# 解压过滤文件恢复

## 行为

解压入库和已有文件夹处理命中过滤规则时，不再直接永久删除文件。系统会先把直接命中的文件或目录保存到任务恢复区，再继续扁平化和分类入库。

默认的无 SE 规则只匹配明确带有 `SEなし`、`无 SE`、`CUT`、`反转` 等排除语义的名称；`SEあり`、普通 `SE.wav` 和 `soundtrack.wav` 不应命中。

- 任务中心文件树仍用“已删除”展示尚未还原的过滤项。
- 右键直接命中的文件或目录可选择“还原文件”或“还原目录”。
- “随目录删除”的子项不能单独还原，必须还原对应的直接删除目录。
- 还原成功后显示“已还原”，并从“只看已删除”统计中移除。
- 目标已有同名文件或目录时停止还原，不覆盖、不自动改名，恢复内容继续保留。
- 只有本功能上线后产生且带 `recovery_id` 的新任务可恢复；历史任务只保留原删除记录。

## 存储与生命周期

恢复数据位于运行数据目录：

```text
data/filter-recovery/<task_id>/
```

桌面版优先使用 `DATA_PATH`；未设置时根据运行配置文件位置解析数据目录。Docker 默认落在 `/app/data/filter-recovery`，因此必须继续持久化挂载 `/app/data`。

恢复数据与任务记录同生命周期。删除任务记录时会先删除对应恢复目录；清理失败会阻止删除任务记录，避免形成没有管理入口的孤立数据。

## 性能边界

- 过滤目录只遍历一次，同一份快照同时用于音频格式统计、文件树和过滤计划。
- 目录规则先归并父子关系；父目录已命中时不再重复保存其子文件。
- 恢复区与解压目录在同一磁盘时使用原子移动，不复制文件内容。
- 跨磁盘时使用 `.part` 暂存和流式文件复制，校验大小并原子发布后才删除原内容。
- 本地还原完成后只提交目标子树的库存索引更新；群晖还原复用现有单文件/目录上传链路，不触发整库扫描。

## API

```http
POST /api/task-center/{item_id}/filtered-items/{recovery_id}/restore
```

仅 `completed` 或 `waiting_manual` 且已经确定最终入库路径的引擎任务可调用。目标同名返回 `409`；旧任务、恢复项丢失、路径非法或任务状态不允许返回 `400`。

# ASMR 增强下载断点续传

## 下载缓存

- 每个增强下载会话固定使用一个 `storage.temp_path/asmr_enhanced/<RJ>_<task-id>` 工作目录。
- 未完成文件使用 `<文件名>.downloading` 保存；源站断流后保留该文件。
- 同一任务的网络重试和用户点击重试都复用原工作目录，通过 HTTP `Range` 从已有字节继续下载。
- 重试时原工作目录不存在会直接报错，不会静默创建新目录从零下载。
- 入库归类模式提交下载前必须选择目标库存；直放已有路径模式使用已定位的库存路径，不受此限制。

## 部分失败

- 只要会话仍有失败资源，就保留整个工作目录，不执行重命名、分类或入库。
- 单文件重试会保留未选中的其他失败资源；会话只有在失败资源清零后才执行一次最终入库。
- 任务中心、后台下载卡片和通知均将“有成功文件且仍有失败文件”显示为部分失败。
- 会话统计按原始选择总数和当前剩余失败数累计，不被最后一轮重试的文件数覆盖。

## 暂停恢复与实时速度

- 下载任务的总进度按所有选择文件的 `transferred_bytes / total_bytes` 计算；文件完成数量只记录业务里程碑，不再将“小文件已完成 8/9”推成任务已完成 81%。任务引擎保留准备、下载、入库的阶段范围，下载工作台和后台小窗直接读取字节进度。
- 总下载速度按同一采样窗口内整批字节增量计算，不能累加各文件的历史平均速度；逐文件速度使用各自独立的增量窗口，文件行只显示自己的速度。高频回调累计字节，窗口达到 350 ms 才移动采样起点。
- 已下载缓存复用和断点基线计入完成字节，但不计入当期网络吞吐；重试导致字节回退时同步调整采样基线，避免速度虚高或等待旧字节量被追平。
- 下载运行态使用独立的 `download_runtime` 事件原因，与进度日志去重分离。即使整数百分比和当前文件文案完全不变，速度和字节仍持续发送。普通回调每任务最多每 750 ms 发布一次，完成、失败、复用边界立即发布。
- 高频运行态只更新 Redis 和 SSE，不进入 PostgreSQL 任务快照队列；文件完成、生命周期变化继续按原业务链持久化。已有文件的回调只更新当前行及汇总贡献，不遍历全文件列表；Redis 预览仅截取前 120 行。
- SSE 通过 `download_file_changes` 发送白名单文件变化项，不发送完整文件树或资源下载地址。前端同一任务的事件批处理合并变化项；小窗、弹窗底栏消费同一套后端总字节、总速度，底栏剩余量包含尚在等待的任务。
- 完整文件列表和 compact 快照按文件更新时间合并，迟到请求不能覆盖较新的文件进度。实时变化可能提前带来第 120 行之后的文件，因此展开完整明细从偏移 0 分页读取，并与请求期间收到的变化合并，不能将当前数组长度作为分页偏移。ASMR 页面移除事件后额外拉取 compact 明细的临时刷新路径。
- 暂停会清零运行态的活跃文件数、速度和预计剩余时间，保留逐文件已传输字节。
- 会话恢复时，在引擎发布恢复事件前，按保留的逐文件进度重建一次活跃文件数，并将运行态状态从 `paused` 切回 `processing`。通过任务中心等入口直接恢复引擎任务时，首个下载进度回调完成同样的状态切换。
- 总下载速度和各文件的速度采样窗口均从恢复时重新开始，暂停等待时间不参与吞吐计算；积累到有效采样窗口后显示速度和预计剩余时间。排队、失败文件不计为活跃下载。
- 重建只发生在暂停到恢复的切换点；高频下载回调继续使用原有增量计数和字节采样，不增加全文件扫描，不改成逐文件速度相加。
- 回归验证：`backend/tests/test_asmr_resource_service.py` 覆盖并发文件多次暂停恢复、恢复事件中的运行态、暂停时间排除和文件完成后的活跃计数归零。
- 事件与性能回归：`backend/tests/test_asmr_download_realtime.py` 通过真实任务文件调度链模拟 8 小文件加 1 大视频；运行态测试验证整数进度不变时持续发布、10 秒内 10,000 次回调仅发布 14 次普通事件及完成边界即时发布，禁止回调扫描文件列表；`test_task_progress_logging.py` 验证高频下载运行态不排队写数据库。
- 前端回归：`transferTaskEvent.test.js` 覆盖批处理变化合并、150 行完整列表及迟到快照；`DownloadTaskWorkbenchDialog.test.js` 覆盖 SSE 到文件行展示、单文件速度与总速度分离、与小窗一致的字节统计和等待任务剩余量。

## 旧数据

修复前已经搬入库存的 `.downloading` 文件不自动回迁。它们可能分散在同一作品目录下的多个 `RJ...`、`RJ...(1)` 子目录，自动合并存在覆盖完整文件的风险，应先按文件大小或校验值确认后再人工整理。

## 本地入库与事件循环

- 普通本地入库在工作线程执行目录创建、文件大小读取、打开、分块读写、flush、fsync、关闭、原子替换与临时文件清理；慢磁盘不会阻塞 HTTP / SSE 所在的主事件循环。
- 每次只传递一个 256 KiB 块的读写任务；暂停、取消检查及进度回调仍在事件循环执行，不在线程内修改任务状态。
- 复制、同步、发布及清理共用 `disk_io_local` 预算。文件同步成功并关闭句柄、再次检查暂停和取消后，才原子替换目标；失败或提前取消保留原目标并清理临时文件。
- 协程取消时等待当前磁盘操作结束，再关闭句柄并清理，避免后台线程继续操作已关闭的文件。已完成的原子替换不撤销。
- 同目录树补全的 `move_source` 路径保留原子发布，目录创建、stat 与替换也全部在线程执行。
- 回归验证：`backend/tests/test_asmr_local_upload_io.py` 人为阻塞磁盘操作，验证其他协程仍能运行，并覆盖暂停、取消、同步失败和原子发布。
